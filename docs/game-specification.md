# ハジケマージ！ ゲーム仕様書

最終更新: 2026-08-04

## 1. 概要

「ハジケマージ！」は、スマートフォンの縦画面で遊ぶ、ピンボールとマージゲームを組み合わせたカジュアルゲームである。

プレイヤーは画面右下の発射ボタンを長押しし、長押し時間に応じた勢いで「ハジケタマ」を発射する。発射されたハジケタマはピンボール台のバンパーに弾かれながらフィールドへ入り、同じレベルのハジケタマ同士が接触すると1段階上へマージする。

フィールドが球で埋まり、危険ラインを越えた状態が一定時間続くとゲームオーバーとなる。最大レベルのハジケタマを完成させたり、連鎖マージを起こしたりしてハイスコアを目指す。

## 2. 対応環境

### 2.1 対象端末

- スマートフォン
- 縦画面固定
- 片手操作を基本とする

### 2.2 基準アスペクト比

- 基準: 9:16
- 19.5:9などの縦長端末にも対応する
- ノッチ、パンチホール、ホームインジケーターのセーフエリアを考慮する

### 2.3 初期実装方針

MVPでは単一画面のエンドレスモードを実装する。ステージ制、育成、課金、ランキング、オンライン機能は対象外とする。

## 3. コアゲームループ

1. 次に発射されるハジケタマを確認する
2. 発射ボタンを長押ししてパワーをためる
3. 指を離してハジケタマを発射する
4. ハジケタマがバンパーや壁に反射してフィールドへ入る
5. 同レベル同士の接触でマージする
6. 連鎖マージや最大レベル完成で得点を獲得する
7. フィールドが危険ラインを越えるまで繰り返す
8. ゲームオーバー後にスコアとハイスコアを表示する

## 4. 画面構成

```text
┌────────────────────┐
│ スコア    ベスト    一時停止 │
│ ────── 危険ライン ────── │
│   ● バンパー      ●         │
│          ●                  │
│                             │
│      メインフィールド       │ ↑ │
│                             │発│
│   ○  ○    ○                │射│
│ ○   ○○  ○                 │レ│
│                            │｜│

├────────────────────┴─┤
│ NEXT: ○ ○ ○      [長押し]   │

```

### 4.1 上部UI

- 現在スコア
- ベストスコア
- 一時停止ボタン
- 危険ライン

### 4.2 メインフィールド

- ハジケタマが落下、反射、停止、マージする領域
- 固定バンパーを3個配置する
- 左右と下側は壁で囲む
- 上部には危険ラインを表示する

### 4.3 発射レーン

- 画面右端に縦長の発射レーンを設ける
- 発射前のハジケタマは右下に待機する
- 発射されたハジケタマは上方向へ移動し、上部からメインフィールドへ入る
- フィールド上の球に発射口が塞がれない構造とする

### 4.4 下部UI

- 次に出るハジケタマを3個表示する
- 長押し式の発射ボタン
- 長押し中のパワーゲージ

## 5. 操作仕様

### 5.1 発射操作

- 発射ボタンを押している間、パワーが増加する
- 指を離した瞬間に発射する
- 最大チャージ時間は初期値1.5秒とする
- 最大までためた後は最大値を維持する
- 自動発射、暴発、パワーの往復はMVPでは採用しない

### 5.2 発射パワー

長押し時間を0.0〜1.0へ正規化し、最小速度と最大速度の間を補間する。

```text
chargeRatio = clamp(holdTime / maxChargeTime, 0, 1)
launchSpeed = lerp(minLaunchSpeed, maxLaunchSpeed, chargeRatio)
```

初期値の目安:

- maxChargeTime: 1.5秒
- minLaunchSpeed: 発射レーン中段付近まで届く速度
- maxLaunchSpeed: 発射レーン最上部まで確実に届く速度

具体値は採用する物理エンジンに合わせて調整可能な設定値とする。

### 5.3 入力制御

- 1個のハジケタマが発射されてから一定時間、またはフィールド進入が確認されるまで次弾を発射できない
- 発射可能時のみボタンを有効化する
- 一時停止中とゲームオーバー中は入力を無効化する

## 6. ハジケタマ

### 6.1 基本設定

ハジケタマは丸いモンスターとして表現する。物理判定は円形とする。

MVPではレベル1〜8を用意する。

| レベル | 仮表示 | 半径倍率 | 備考 |
|---:|---|---:|---|
| 1 | 数字1の球 | 1.00 | 主な出現球 |
| 2 | 数字2の球 | 1.08 | 出現候補 |
| 3 | 数字3の球 | 1.16 | 低確率で出現 |
| 4 | 数字4の球 | 1.24 | マージ生成のみ |
| 5 | 数字5の球 | 1.32 | マージ生成のみ |
| 6 | 数字6の球 | 1.40 | マージ生成のみ |
| 7 | 数字7の球 | 1.48 | マージ生成のみ |
| 8 | 数字8の球 | 1.56 | 最大レベル |

半径倍率は暫定値であり、実機テストで調整する。

### 6.2 表示

MVPでは以下の簡易表現でよい。

- レベルごとに異なる色
- 中央にレベル番号
- 丸い輪郭
- マージ時に拡大、発光、パーティクルを表示

将来的には各レベルを丸いモンスターのイラストへ置き換える。

## 7. 出現ルール

### 7.1 出現レベル

発射されるのはレベル1〜3のみとする。

初期の構成比:

- レベル1: 70%
- レベル2: 25%
- レベル3: 5%

### 7.2 バッグ方式

完全ランダムではなく、バッグ方式を採用する。

初期バッグ例:

```text
[Lv1, Lv1, Lv1, Lv1, Lv1, Lv2, Lv2, Lv3]
```

- バッグ内をシャッフルする
- 先頭から1個ずつ取り出す
- 空になったら新しいバッグを生成する
- NEXT欄には先頭3個を表示する

これにより、極端な偏りを防止する。

## 8. 物理挙動

### 8.1 基本挙動

- 重力あり
- 壁、バンパー、ハジケタマ同士で衝突する
- 回転を許可する
- 反発係数と摩擦係数は設定ファイルで調整可能にする
- 長時間微振動し続けないよう、一定以下の速度ではスリープさせる

### 8.2 初期パラメータ方針

- ハジケタマ同士: やや低めの反発
- 壁: 中程度の反発
- バンパー: 強い反発
- 床: 低反発、高めの摩擦

数値はエンジン依存のため、ゲーム設定として外出しする。

### 8.3 安定化

- 高速移動時のすり抜けを防ぐため、連続衝突判定を使用する
- 同一フレームで同じ球が複数回マージしないようロックする
- マージ対象となった球は直ちに操作対象と衝突対象から除外する

## 9. バンパー

### 9.1 MVP構成

固定バンパーを3個配置する。

- 上部左
- 上部右
- 中央付近

### 9.2 挙動

- ハジケタマが接触すると、接触法線方向へ追加インパルスを与える
- 接触時に軽い拡縮アニメーションを行う
- 接触音と小さなパーティクルを再生する

### 9.3 MVP対象外

- フリッパー
- 回転バー
- ワープ
- 球の種類を変えるゲート
- 球を破壊する障害物
- プレイヤーによるバンパー配置

## 10. マージ仕様

### 10.1 マージ条件

以下をすべて満たす場合にマージする。

- 2個のハジケタマが同じレベルである
- 両方がマージ処理中ではない
- 両方が最大レベル未満である
- 接触開始から0.1秒以上経過している

接触時間は設定値とする。試作時には即時マージとの比較も可能にする。

### 10.2 マージ処理

1. 対象の2球をマージ中としてロックする
2. 2球の位置、速度、質量を取得する
3. 2球を削除する
4. 中間地点に1段階上の球を生成する
5. 生成球へ平均速度を引き継ぐ
6. 小さな追加インパルスを与える
7. マージ演出と効果音を再生する
8. スコアを加算する

生成位置:

```text
mergePosition = (positionA + positionB) / 2
```

基本速度:

```text
mergeVelocity = (velocityA + velocityB) / 2
```

必要に応じて衝突方向へ追加インパルスを与え、連鎖が起こりやすい手触りにする。

### 10.3 連鎖

マージ生成球が短時間内に再びマージした場合、コンボ数を増加させる。

初期案:

- コンボ受付時間: 1.5秒
- 2連鎖: 得点倍率1.2
- 3連鎖: 得点倍率1.5
- 4連鎖以上: 以降0.25ずつ加算

倍率と受付時間は設定値とする。

### 10.4 最大レベル

レベル8が生成された場合:

1. 最大レベル完成演出を行う
2. 大量得点を加算する
3. 周囲へ衝撃波を発生させる
4. 約1秒後にレベル8の球をフィールドから削除する

これにより、最大レベル球がフィールドを占有し続けることを防ぐ。

## 11. スコア

### 11.1 基本点

暫定案:

```text
baseScore = 10 × 2^(生成後レベル - 1)
```

例:

| 生成レベル | 基本点 |
|---:|---:|
| 2 | 20 |
| 3 | 40 |
| 4 | 80 |
| 5 | 160 |
| 6 | 320 |
| 7 | 640 |
| 8 | 1280 |

最大レベル完成時は追加ボーナスを加算する。

### 11.2 コンボ倍率

```text
獲得点 = 基本点 × コンボ倍率
```

### 11.3 ハイスコア

- 端末ローカルへ保存する
- ゲームオーバー画面で今回スコアとベストスコアを表示する

## 12. ゲームオーバー

### 12.1 危険ライン

メインフィールド上部に危険ラインを設置する。

### 12.2 判定条件

次の条件をすべて満たした状態が2.0秒継続した場合、ゲームオーバーとする。

- 危険ラインより上に球の一部が存在する
- 対象球の速度が停止判定値以下である
- 対象球が発射レーン内ではない
- 対象球がマージ演出中ではない

バンパーによって一時的に上へ跳ねただけの球ではゲームオーバーにしない。

### 12.3 警告表示

- 条件を満たし始めたら危険ラインを点滅させる
- 2秒の猶予を視覚的に示す
- 条件が解除されたらカウントをリセットする

### 12.4 ゲームオーバー後

- 物理シミュレーションを停止する
- 最終スコアを表示する
- ベスト更新時は専用表示を出す
- 「もう一度」と「タイトルへ」を表示する

MVPでタイトル画面を省略する場合、「もう一度」のみでもよい。

## 13. ゲーム状態

最低限、以下の状態を明確に分離する。

```text
Initializing
Ready
Charging
Launching
Resolving
Paused
GameOver
```

### 13.1 状態遷移例

```text
Initializing → Ready
Ready → Charging
Charging → Launching
Launching → Resolving
Resolving → Ready
任意のプレイ状態 → Paused
Paused → 直前の状態
任意のプレイ状態 → GameOver
GameOver → Initializing
```

## 15. 一時停止

- 物理シミュレーションを停止する
- チャージ中に一時停止された場合はチャージをキャンセルする
- 再開、リスタート、終了を選択できる
- MVPでは再開とリスタートのみでもよい

## 16. データ保存

MVPで保存する項目:

- ベストスコア
- サウンド設定
- 初回起動済みフラグ

保存失敗時でもゲーム進行を妨げない。

## 19. 受け入れ条件

MVP完成と判断する最低条件:

1. スマートフォン縦画面でUIが破綻しない
2. 発射ボタンの長押し時間により、球の到達位置が明確に変わる
3. 同レベルの球同士が安定してマージする
4. 同一球の二重マージや無限生成が発生しない
5. バンパー接触で球が明確に弾かれる
6. NEXT表示と実際の出現順が一致する
7. 最大レベル完成後、演出を経て球が退出する
8. 一瞬のライン越えではゲームオーバーにならない
9. 停止した球が危険ラインを2秒越えるとゲームオーバーになる
10. リスタート後に前回の物理オブジェクトやタイマーが残らない
11. ベストスコアがアプリ再起動後も保持される
12. 30回以上連続プレイしてクラッシュしない

## 20. 実装上の推奨構成

採用エンジンに依存しない責務分割の例:

```text
GameManager
├─ GameStateController
├─ LauncherController
├─ BallSpawner
├─ MergeSystem
├─ ScoreSystem
├─ ComboSystem
├─ DangerLineController
├─ SaveSystem
├─ AudioController
└─ UIController
```

### 20.1 ハジケタマのデータ

```text
BallData
- level
- radius
- mass
- restitution
- friction
- scoreValue
- visualId
```

### 20.2 実行中オブジェクト

```text
BallEntity
- uniqueId
- level
- isMerging
- isInLaunchLane
- rigidBody reference
- contact tracking
```

### 20.3 マージ排他制御

- マージ候補の組を一意なID順で処理する
- 1フレーム内の候補をキューへ積む
- 同じ球を含む後続候補は破棄する
- 物理コールバック内で直接生成、削除を完結させず、フレーム末尾に処理する

### 21.1 発射

1. 縦画面と物理フィールド
